# Aliasing and Antialiasing

Suppose you want to render a straight line one pixel wide. A mathematical line has zero geometric width and would be invisible; rendering software represents it as a thin rectangular band one pixel across. When this band runs purely horizontal or vertical, it aligns exactly with a row or column of pixels. When tilted at an angle, however, the band covers some pixels completely, some partially, and some only at a corner.

Because a pixel in a frame buffer can store only one color value at a time, rendering software must decide how to handle pixels that are only partially covered.

## Aliasing: all or nothing

The simplest rendering approach tests each pixel once at its geometric center. If the center lies inside the line boundary, the pixel is set to black; otherwise, it remains white. Every pixel is evaluated as an all-or-nothing decision. Rotate the line below to inspect the result:

A tilted line rendered this way breaks into a visible staircase pattern. Whenever the path crosses into the next row or column, it jumps by an entire pixel, forming a sudden step often called a **dogleg**. These stair-step artifacts are called **jaggies**, and the visual distortion is known as **aliasing** (or stair-stepping). Aliasing appears along diagonal edges, curves, vector font outlines, and any slanted or curved edge.

In [signal sampling](/courses/computational-mathematics/sound-and-sampling#sampling-what-44100-per-second-means), taking too few measurements makes a fast signal masquerade as a slower one, becoming an "alias" of itself. In the same way, sampling a continuous line at discrete pixel centers maps different exact positions onto the same pixel coordinates, so those lines share the same stepped pixel "alias."

## Antialiasing: partial coverage, partial color

**Antialiasing** refers to rendering techniques that minimize the visibility of jaggies. Instead of forcing an all-or-nothing decision, the renderer calculates what fraction of the pixel area the shape covers and blends the foreground and background colors in that exact proportion (using the [alpha-blending rule](/courses/computer-graphics/color-pixels#32-bit-color-adding-alpha) from Module 0). If a black line (0) on a white background (255) covers 40% of a pixel, that pixel blends 40% black with 60% white:

$$
255 \times (1 - \text{coverage}) = 255 \times (1 - 0.40) = 255 \times 0.60 = 153
$$

At 50% coverage, $255 \times 0.50 = 127.5$, which rounds to 128 (medium gray).

Switch the visualizer above to **Antialiased**. The demo approximates coverage by sampling each pixel across a 4 × 4 grid of 16 sample points. The pixel darkness corresponds to the fraction of sample points inside the line boundary. If 6 of the 16 points fall within the line, the coverage is $6 \div 16 = 37.5\%$, giving a brightness of $255 \times (1 - 0.375) \approx 159$. Viewed close up, the line edges appear softly blurred with gray pixels; at normal viewing distances, human vision integrates those intermediate shades into a clean, continuous boundary.

Computing the exact overlap area between every shape and millions of pixels is computationally demanding. Practical rendering engines approximate coverage by testing multiple sample points inside each pixel, a technique known as **supersampling**.

<Callout tone="orange" label="Antialiasing modifies color, not resolution">
Antialiasing does not increase the physical resolution or add genuine geometric detail to an image. It replaces sharp, stepped pixel boundaries with calibrated intermediate shades that appear smooth to the eye. The output remains a discrete pixel grid.
</Callout>

## Back to the canvas line

This explains the line artifact observed in the [previous lesson](/courses/computer-graphics/pixel-coordinates). On an HTML canvas with antialiasing enabled, drawing a one-pixel horizontal line along an integer coordinate boundary places the stroke across the border between two pixel rows. Because the stroke covers exactly 50% of each row, both rows are shaded 50% gray, resulting in a blurry two-pixel-wide line. Shifting the line coordinate by 0.5 pixels centers the stroke entirely within a single row, giving 100% coverage and producing a solid black, one-pixel-wide line.

## Three ways to fight jaggies

Graphics pipelines reduce stair-step artifacts through three primary strategies:

1. **Increase physical pixel density.** Higher resolution displays feature smaller physical pixels, reducing the visible width of individual stair steps. At densities above 400 PPI on mobile screens, individual steps are nearly imperceptible to the naked eye.
2. **Antialias during rendering.** Calculate geometric coverage or test multiple sample points inside each pixel during rasterization to shade border pixels proportionally.
3. **Filter the finished image.** Apply a blur filter after rasterization (called **post-processing**), such as a **Gaussian blur**, which computes [weighted averages](/courses/computational-mathematics/averaging-is-convolution#step-1-multiply-and-add) of neighboring pixels to soften hard steps.

<PracticalApplication title="Real-time rendering" tool="MSAA, FXAA, TAA">
Video games and GPU applications use hardware-accelerated variants of these methods. Multisample antialiasing (MSAA) checks multiple depth and coverage points inside each pixel along triangle edges while running the expensive color calculation only once per pixel. Fast post-processing methods like FXAA (Fast Approximate Antialiasing) and TAA (Temporal Antialiasing) scan the finished frame, or blend consecutive frames, to smooth jagged edges at low cost.
</PracticalApplication>

<PracticalApplication title="Text and typography" tool="Subpixel font rendering">
Operating system font engines apply antialiasing to all vector typefaces. Advanced rendering systems manipulate the physical red, green, and blue [subpixels](/courses/computer-graphics/flat-panels) on flat-panel displays independently, effectively tripling the horizontal sampling resolution for character edges.
</PracticalApplication>
