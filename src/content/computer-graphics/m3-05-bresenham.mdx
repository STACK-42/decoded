# Bresenham's Line Algorithm

While [DDA](/courses/computer-graphics/dda) simplifies line drawing, it still requires floating-point additions and explicit rounding at every pixel. Jack Bresenham developed an algorithm that plots the exact same discrete pixels using **only integer arithmetic**: additions, subtractions, and [bit shifts](/courses/microprocessors/arithmetic-and-logic#shifts-and-rotates) (since doubling integers like $2\Delta y$ and $2\Delta x$ is a single 1-bit left shift on hardware). By avoiding floating-point units entirely, Bresenham's formulation delivered high performance on early hardware and remains the fundamental standard for rasterizing lines.

## The core decision

Consider a line with a gentle slope ($0 \le m \le 1$). As in DDA, the algorithm advances $x$ by 1 on each step. Having illuminated pixel $(x_k, y_k)$, the next pixel must lie in column $x_k + 1$. Because the slope does not exceed 1, there are only two candidate locations for the next pixel:

- **Stay** on the current row: $(x_k + 1, y_k)$
- **Move up** to the adjacent row: $(x_k + 1, y_k + 1)$

The line cannot climb two rows in a single column step. The algorithm therefore evaluates a binary decision at each step: which candidate pixel center is closer to the continuous line? Equivalently, has the true line crossed the **midpoint** between the two candidate pixels?

DDA resolves this by computing floating-point $y$ and rounding. Bresenham's algorithm instead tracks an integer **decision parameter** $p_k$, whose *sign* dictates the correct pixel selection.

## The decision parameter

The derivation in the next section yields an integer decision rule starting from $\Delta x = x_2 - x_1$ and $\Delta y = y_2 - y_1$:

$$
p_0 = 2\Delta y - \Delta x
$$

At each successive step $k$:

- If $p_k < 0$, the continuous line lies below the midpoint: **stay** on the current row ($y_{k+1} = y_k$), and update $p_{k+1} = p_k + 2\Delta y$.
- If $p_k \ge 0$, the continuous line lies on or above the midpoint: **move up** one row ($y_{k+1} = y_k + 1$), and update $p_{k+1} = p_k + 2\Delta y - 2\Delta x$.

Every quantity in this formulation is an integer. The constants $2\Delta y$ and $2\Delta y - 2\Delta x$ are precalculated once before the loop begins, reducing each per-pixel step to a single sign comparison and an integer addition.

## Derivation of the formula

At column $x_k + 1$, the mathematical line has continuous height $y = m(x_k + 1) + c$. Define the vertical offsets from this line to the lower pixel center $y_k$ and upper pixel center $y_k + 1$:

$$
d_1 = y - y_k \qquad d_2 = (y_k + 1) - y
$$

Because $d_1$ measures how far the line is above the lower pixel, $d_1 \ge d_2$ means the lower pixel is farther away, so the upper pixel is closer (or tied). Expanding $d_1 - d_2$:

$$
d_1 - d_2 = (y - y_k) - (y_k + 1 - y) = 2y - 2y_k - 1 = 2m(x_k + 1) - 2y_k + 2c - 1
$$

This expression contains the fraction $m = \Delta y / \Delta x$. Multiplying through by $\Delta x$ (which is positive for lines moving left-to-right) clears the denominator without changing the sign, giving $p_k$:

$$
\begin{aligned}
p_k = \Delta x\,(d_1 - d_2) &= 2\Delta y\,(x_k + 1) - 2\Delta x\,y_k + \Delta x(2c - 1) \\
&= 2\Delta y \cdot x_k - 2\Delta x \cdot y_k + b
\end{aligned}
$$

where $b = 2\Delta y + \Delta x(2c - 1)$ is a constant that stays the same across every step.

### Recursive update rules

Subtracting $p_k$ from $p_{k+1}$ eliminates the constant $b$. Because $x$ advances by exactly 1 on every step ($x_{k+1} - x_k = 1$):

$$
p_{k+1} - p_k = 2\Delta y\,(x_{k+1} - x_k) - 2\Delta x\,(y_{k+1} - y_k) = 2\Delta y - 2\Delta x\,(y_{k+1} - y_k)
$$

- If the line stays on the same row ($y_{k+1} - y_k = 0$), the parameter changes by $p_{k+1} = p_k + 2\Delta y$.
- If the line steps upward ($y_{k+1} - y_k = 1$), the parameter changes by $p_{k+1} = p_k + 2\Delta y - 2\Delta x$.

### Initial parameter value

Because the starting endpoint $(x_0, y_0)$ lies on the line, $c = y_0 - (\Delta y / \Delta x) x_0$, so $\Delta x \cdot c = \Delta x\,y_0 - \Delta y\,x_0$. Substituting into $p_0 = 2\Delta y\,x_0 - 2\Delta x\,y_0 + 2\Delta y + 2\Delta x\,c - \Delta x$:

$$
p_0 = 2\Delta y\,x_0 - 2\Delta x\,y_0 + 2\Delta y + 2\Delta x\,y_0 - 2\Delta y\,x_0 - \Delta x = 2\Delta y - \Delta x
$$

Bresenham's algorithm preserves the exact nearest-pixel decision of DDA, but scales the metric by $\Delta x$ so that all operations execute in integer arithmetic.

## Worked example: (20, 10) to (30, 18)

For endpoints $(20, 10)$ and $(30, 18)$: $\Delta x = 10$, $\Delta y = 8$, yielding precalculated constants $2\Delta y = 16$ and $2\Delta y - 2\Delta x = 16 - 20 = -4$.

The initial decision parameter is:
$$
p_0 = 2 \times 8 - 10 = 6
$$

## Equivalence to DDA

Evaluating endpoints $(5, 4)$ and $(12, 7)$ (the first DDA example) with Bresenham's formulation gives $\Delta x = 7$, $\Delta y = 3$, and $p_0 = 2(3) - 7 = -1$. The algorithm plots $(5, 4)$, $(6, 4)$, $(7, 5)$, $(8, 5)$, $(9, 6)$, $(10, 6)$, $(11, 7)$, $(12, 7)$, matching the exact pixel path produced by DDA. Bresenham's algorithm does not generate a different geometric path; it makes the identical nearest-pixel decision using exact integer logic without cumulative drift.

## Steep lines and general octants

The basic derivation assumes lines in the **first octant** (the $0°$ to $45°$ wedge where $x$ increases rightward and $0 \le m \le 1$). Dividing the circle around a point into eight $45°$ wedges gives eight octants, and other orientations adapt the same logic:

- **Steep lines ($\lvert m \rvert > 1$)**: Swap coordinate roles. The inner loop steps along $y$ by single units, using the decision parameter to determine whether $x$ increments.
- **Negative slopes and backward paths**: Increment coordinates by $-1$ instead of $+1$ along the appropriate axis. The decision logic remains identical using absolute values $\lvert\Delta x\rvert$ and $\lvert\Delta y\rvert$.

## DDA compared with Bresenham

| Attribute | DDA | Bresenham |
|---|---|---|
| Arithmetic | Floating-point operations | Integer arithmetic only |
| Cost per pixel | Additions and rounding operations | One comparison and one addition |
| Numerical accuracy | Accumulates fractional rounding drift | Exact integer precision |
| Derivation effort | Intuitive continuous formulation | Requires parameter derivation |

Graphics literature also features the **Gupta-Sproull algorithm**, an extension of Bresenham's technique incorporating [antialiasing](/courses/computer-graphics/aliasing#antialiasing-partial-coverage-partial-color). As it advances along the line, Gupta-Sproull calculates perpendicular distances to neighboring pixels and shades them proportionally, producing smooth boundaries without jagged steps.
