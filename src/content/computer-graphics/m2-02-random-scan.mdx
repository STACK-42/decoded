# Random Scan Displays

A raster CRT sweeps across every row regardless of what is on screen. A **random-scan display**, also known as a **vector display**, is a CRT that steers its electron beam differently: the beam travels only where lines appear in the drawing, tracing each line segment directly from one coordinate to another like a mechanical pen drawing on paper.

Here, "random" does not mean chaotic or unpredictable. It means the beam can jump directly to any coordinate on the screen, like addressing [random-access memory](/courses/computer-organization/ram-and-rom#primary-memory-four-kinds-of-chip), rather than following a predetermined top-to-bottom raster sweep.

## The display file

A random-scan system does not store a grid of pixels. Instead, it stores an ordered list of drawing commands called the **display file** (also called a display list or display program): instructions like "line from (2, 13) to (13, 13)" and "line from (13, 13) to (13, 6)".

1. Your program describes the drawing to a **graphics package** (a software library providing drawing commands).
2. The graphics package converts those shapes into basic line instructions and writes them to the display file in memory.
3. A dedicated **display processor** (often called a **display processing unit** or **graphics controller** in vector hardware) reads commands sequentially from the display file and steers the electron beam directly along each line.
4. When the display processor reaches the end of the list, it loops back to the first instruction, repeatedly redrawing the picture to maintain phosphor glow.

## Raster against random

| | Raster scan | Random scan |
|---|---|---|
| Beam path | Every row, top to bottom, every frame | Only along the lines in the picture |
| Memory stored | A frame buffer: one value per pixel | A display file: a list of line commands |
| Line appearance | Jagged on diagonals (stair steps) | Smooth continuous lines |
| Shading and photos | Realistic shaded scenes, millions of colors | Lines only, no realistic shaded scenes |
| Refresh time | Fixed, regardless of screen content | Increases with the number of lines |
| Hardware bottleneck | Needed costly RAM for early frame buffers | Needed fast deflection amplifiers for jumps |

The core trade-off comes down to scene complexity versus filled surfaces. **Random-scan displays draw crisp, unstepped lines, but they cannot fill solid regions or render photographs**: trying to hatch a solid shape with hundreds of tight lines pushes the display file past the phosphor's brief glow time, making the screen flicker before the beam finishes the loop. Raster displays handle arbitrary filled shapes, lighting, and photos in fixed refresh time, at the cost of stair-stepping on diagonal edges.

<Callout tone="orange" label="Which display was expensive?">
Older textbooks often list raster displays as expensive because of the frame buffer. Storing a dedicated color value for every pixel on screen required substantial memory when RAM was costly. In contrast, early random-scan systems saved memory by storing only short command lists, but needed complex, high-speed deflection amplifiers so the beam could jump rapidly to arbitrary coordinates rather than sweeping steadily row by row. When semiconductor memory prices dropped, raster displays became far cheaper because the rest of the unit reused mass-produced television components.
</Callout>

<Callout tone="sky" label="Why raster won">
Real-world images depend on filled surfaces, shading, and texture. Once memory became inexpensive, raster displays handled both text and realistic pictures at low cost. Dedicated random-scan hardware now survives primarily in the **oscilloscope**, a laboratory instrument that plots electrical waveforms as continuous curves. The underlying concept remains central to modern graphics: a display file is the hardware ancestor of the [vector image](/courses/computer-graphics/raster-and-vector-images), which remains the standard for fonts and scalable illustrations.
</Callout>
