# States, Symbols, and Transitions

In Module 0 you traced strings through diagrams to tell whether a machine accepts or rejects them. Pictures are easy to read, yet two people looking at different diagrams still need a shared notation to compare machines, prove facts about them, or combine them.

The formal definition gives you that notation, letting you reason about machines the way you reason about equations.

## Deterministic Finite Automaton Definition

A **Deterministic Finite Automaton** is defined as a **five-tuple** (an ordered list of five components, where position matters):

$$
M = (Q,\ \Sigma,\ \delta,\ q_0,\ F)
$$

Each of the five components maps directly to something you've seen in the diagrams.

**$Q$** is the finite set of all states: every circle in the diagram.

$$
Q = \{q_0,\ q_1,\ q_2\}
$$

**$\Sigma$** is the [alphabet](/courses/theory-of-computation/language-of-languages#alphabet-sigma), the finite set of symbols the machine is allowed to read. A symbol outside $\Sigma$ never appears in its input.

$$
\Sigma = \{a,\ b\}
$$

**$\delta$** is the **transition function** (the arrows). Here $Q \times \Sigma$ is the set of all pairs $(q, a)$ built from one state $q \in Q$ and one symbol $a \in \Sigma$. The function takes one such pair and returns the single next state:

$$
\delta : Q \times \Sigma \rightarrow Q
$$

Given any state in $Q$ and any symbol in $\Sigma$, $\delta$ returns one next state with no ambiguity. That single-output rule is what makes the machine *deterministic*.

**$q_0$** is the **initial state** (also called the **start state**), where computation always begins. $q_0 \in Q$.

**$F$** is the set of [accept states](/courses/theory-of-computation/how-to-read-a-machine#the-anatomy-of-a-state-diagram) (also called **final states**), the double circles. $F \subseteq Q$. Because $F$ can be *any* subset of $Q$, a DFA can have zero accept states ($F = \emptyset$, rejecting every string), can include the start state ($q_0 \in F$, meaning the empty string is accepted), or can make every state accepting ($F = Q$). If the machine runs out of input while its current state is in $F$, it accepts the input.

<Callout tone="violet" label="Why a five-tuple">
  Five components are the minimum needed to fully specify a [DFA](/courses/theory-of-computation/how-to-read-a-machine#what-dfa-means). Give someone these five and they can reconstruct the diagram exactly, and they can also reason about the machine mathematically without drawing it.
</Callout>

Written as a five-tuple:

$$
Q = \{q_0,\ q_1,\ q_2\}
$$

$$
\Sigma = \{a,\ b\}
$$

$$
q_0 = q_0 \qquad F = \{q_2\}
$$

The fourth component of the tuple says which state in $Q$ is the start state, which here happens to be named $q_0$ (in another machine, the start state could just as well be named $s$ or $A$).

And the transition function $\delta$ as a table, with one entry for every state and symbol:

$$
\begin{array}{c|cc}
\delta & a & b \\
\hline
q_0 & q_1 & q_0 \\
q_1 & q_1 & q_2 \\
q_2 & q_1 & q_0 \\
\end{array}
$$

Each row is a state, each column a symbol, and each cell is where $\delta$ sends you: for instance, row $q_1$ and column $b$ holds $q_2$, meaning $\delta(q_1, b) = q_2$. The table and the diagram describe the same machine in two ways.

<Callout tone="orange" label="The transition table must be complete">
  Every cell in the table must be filled, because every state needs a transition for every symbol in $\Sigma$. With $3$ states and $2$ symbols, the table has $3 \times 2 = 6$ cells and none can be left blank. A machine with a missing transition is no longer a DFA. This is one of the differences between a DFA and an [NFA](/courses/theory-of-computation/nfa), which you'll meet in the next lesson.
</Callout>

## The Extended Transition Function: $\hat{\delta}$

$\delta$ handles one symbol at a time, but what you care about is what happens after reading a whole string. For that, mathematicians define $\hat{\delta}$ (delta-hat), the **extended transition function**, which works on strings from $\Sigma^*$ instead of single symbols:

$$
\hat{\delta} : Q \times \Sigma^* \rightarrow Q
$$

$$
\hat{\delta}(q,\ \varepsilon) = q
$$

Reading the [empty string](/courses/theory-of-computation/language-of-languages#string-word) from any state leaves you in that state, because zero symbols have been consumed.

$$
\hat{\delta}(q,\ wa) = \delta(\hat{\delta}(q,\ w),\ a)
$$

Reading a non-empty string $wa$ (any prefix $w \in \Sigma^*$ followed by a final symbol $a \in \Sigma$) works in two steps: first process $w$ from $q$ to get an intermediate state $\hat{\delta}(q, w)$, then take one final step from there on $a$ using $\delta$.

The definition is recursive: it builds up the computation one symbol at a time, exactly as you did by hand in [How to Read a Machine](/courses/theory-of-computation/how-to-read-a-machine#a-machine-read-by-hand). $\hat{\delta}$ is the formal name for that process.

To see $\hat{\delta}$ in action, run it on the string $ab$ for the machine above. Apply the recursive rule, peeling off one symbol at a time from the right:

$$
\hat{\delta}(q_0,\ ab) = \delta(\hat{\delta}(q_0,\ a),\ b)
$$

To evaluate $\hat{\delta}(q_0, a)$, write the single-symbol string $a$ as $\varepsilon a$ (so $w = \varepsilon$) and apply both rules:

$$
\hat{\delta}(q_0,\ a) = \hat{\delta}(q_0,\ \varepsilon a) = \delta(\hat{\delta}(q_0,\ \varepsilon),\ a) = \delta(q_0,\ a) = q_1
$$

Plug $q_1$ back into the outer step for $ab$:

$$
\hat{\delta}(q_0,\ ab) = \delta(q_1,\ b) = q_2
$$

Now trace a rejected string, $ba$, the same way:

$$
\hat{\delta}(q_0,\ b) = \delta(\hat{\delta}(q_0,\ \varepsilon),\ b) = \delta(q_0,\ b) = q_0
$$

$$
\hat{\delta}(q_0,\ ba) = \delta(\hat{\delta}(q_0,\ b),\ a) = \delta(q_0,\ a) = q_1
$$

The language a DFA $M$ accepts (also called the language **recognized** by $M$) is then defined as:

$$
L(M) = \{w \in \Sigma^* \mid \hat{\delta}(q_0,\ w) \in F\}
$$

That's all strings that, fed to the machine from $q_0$, end in an accept state. For $ab$, the trace ends at $q_2 \in F$, so $ab \in L(M)$. For $ba$, the trace ends at $q_1 \notin F$, so $ba \notin L(M)$. You reached the same conclusions by hand earlier; this time they come straight from the definition, with no diagram involved.

## What "Deterministic" Buys You

Earlier we unpacked the word informally: at every state, every symbol has exactly one transition arrow. Formally, that rule lives in the type of $\delta$ itself:

$$
\delta : Q \times \Sigma \rightarrow Q
$$

The return type is $Q$, not the power set of $Q$, so one input pair always gives one state, which is the entire rule of determinism.

Two consequences follow. First, a DFA simulator is a simple loop: read one character, look up the next state in a table, and never backtrack. That's why regex engines built on DFAs run in time linear in the length of the input. Second, this single-arrow rule is exactly what the next lesson relaxes. An NFA's transition function returns a *set* of states, and the machine explores all of them at once. The diagrams look the same, but the signature differs and the runtime behaves very differently.

<Callout tone="sky" label="Historical note">
  The DFA was formally defined by Warren McCulloch and Walter Pitts in 1943, originally as a mathematical model of how neurons fire, before it was used to describe computation. Kleene then connected it to [regular expressions](/courses/theory-of-computation/regular-expressions#the-notation-and-what-binds-tighter) in 1951. The [parking meter](/courses/theory-of-computation/how-to-read-a-machine#a-first-example-a-parking-meter), the regex engine, and the original neuron model are all instances of the same five-tuple.
</Callout>

## Building Your First DFA

To build a DFA from a language description, follow four steps:

**Step 1: Identify the conditions.** What does the machine need to remember to make the right decision at the end? Each distinct condition becomes a state. Track only the conditions that affect the final answer, not the full history of what it has seen.

**Step 2: Name the states.** One state per condition. Add a [trap state](/courses/theory-of-computation/how-to-read-a-machine#two-important-notes) (also called a **dead state** or **sink state**, one with self-loops on every symbol) if the machine can reach a point where acceptance is impossible regardless of what follows. For example, a machine for "starts with $a$" needs a dead state the moment the first symbol is $b$, whereas "at least one $a$" does not because an $a$ can still show up later.

**Step 3: Fill the transition table.** For every state, for every symbol, decide: if I am in this condition and I read this symbol, what condition am I in now?

**Step 4: Mark the initial and accept states.** Which condition am I in before reading anything? Which conditions represent strings I want to accept?

As a worked example, build a DFA over $\Sigma = \{a, b\}$ that accepts exactly the strings containing at least one $a$.

The conditions that matter:
- $q_0$: haven't seen any $a$ yet, so can't accept yet
- $q_1$: have seen at least one $a$, so accept from here on

Now fill the four transitions one by one:
- From $q_0$ on $a$: we just saw an $a$, so move to $q_1$.
- From $q_0$ on $b$: we still haven't seen an $a$, so stay in $q_0$.
- From $q_1$ on $a$: we already saw at least one $a$, and seeing another doesn't undo that, so stay in $q_1$.
- From $q_1$ on $b$: we still have seen at least one $a$, so stay in $q_1$.

$$
\begin{array}{c|cc}
\delta & a & b \\
\hline
q_0 & q_1 & q_0 \\
q_1 & q_1 & q_1 \\
\end{array}
$$

$q_0$ is initial. $q_1$ is the only accept state (and $\varepsilon$ is rejected because $q_0 \notin F$, which matches "at least one $a$"). Once you reach $q_1$, no symbol can take you back, because "seen at least one $a$" stays true forever.

Check two traces by hand:
- `ba` (accepted): $q_0 \xrightarrow{b} q_0 \xrightarrow{a} q_1 \in F$.
- `bbb` (rejected): $q_0 \xrightarrow{b} q_0 \xrightarrow{b} q_0 \xrightarrow{b} q_0 \notin F$.

Try `a`, `ba`, `bbb`, `bab` in the diagram above too. The machine should accept exactly the strings where at least one `a` appears anywhere.

<Callout tone="orange" label="Common DFA design mistakes">
  Three slips account for most wrong DFAs on exams:
  - **Stopping after reaching $F$:** Leaving out outgoing arrows from $q_1$ once the condition is met. A DFA still has to read the rest of the string, so every accept state needs an arrow for every symbol in $\Sigma$.
  - **Forgetting the empty string:** Always check whether $\varepsilon$ belongs in the language. If it does, $q_0$ itself must be in $F$.
  - **Tracking too much history:** You do not need states for "saw two $a$'s" or "saw $ba$" when the rule only asks for *at least one* $a$. Every state should represent a distinction that changes the final answer.
</Callout>

## Practice by hand

**1. Evaluate $\hat{\delta}$:** Using the ends-in-$ab$ DFA from earlier in this lesson ($\delta(q_0, b) = q_0$, $\delta(q_0, a) = q_1$, $\delta(q_1, a) = q_1$, $\delta(q_1, b) = q_2$), compute $\hat{\delta}(q_0, bba)$ step by step using the recursive definition. Is $bba \in L(M)$?

<ModelAnswer>
Peel one symbol at a time from the right:
1. $\hat{\delta}(q_0, b) = \delta(\hat{\delta}(q_0, \varepsilon), b) = \delta(q_0, b) = q_0$
2. $\hat{\delta}(q_0, bb) = \delta(\hat{\delta}(q_0, b), b) = \delta(q_0, b) = q_0$
3. $\hat{\delta}(q_0, bba) = \delta(\hat{\delta}(q_0, bb), a) = \delta(q_0, a) = q_1$

Since $F = \{q_2\}$ and $q_1 \notin F$, $bba \notin L(M)$ (it ends in $a$, not $ab$).
</ModelAnswer>

**2. Build a DFA table:** Write the five-tuple and complete transition table over $\Sigma = \{a, b\}$ for the language of strings with an **even number of $a$'s** (remembering that zero is even, so $\varepsilon$ is accepted).

<ModelAnswer>
You only need two conditions: seen an even number of $a$'s so far ($q_0$, start and accept), or seen an odd number of $a$'s so far ($q_1$).
- $Q = \{q_0, q_1\}$, $\Sigma = \{a, b\}$, start state $q_0$, $F = \{q_0\}$.
- Every $a$ flips between $q_0$ and $q_1$; every $b$ leaves the parity of $a$'s unchanged:

$$
\begin{array}{c|cc}
\delta & a & b \\
\hline
q_0 & q_1 & q_0 \\
q_1 & q_0 & q_1 \\
\end{array}
$$
</ModelAnswer>
