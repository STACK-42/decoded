# CFG = PDA

Module 1 ended with [Kleene's theorem](/courses/theory-of-computation/kleenes-theorem): [regular expressions](/courses/theory-of-computation/regular-expressions#the-notation-and-what-binds-tighter), finite automata and [transition graphs](/courses/theory-of-computation/transition-graphs) describe the same languages. Module 2 has its own version, with grammars playing the part of regular expressions and [pushdown automata](/courses/theory-of-computation/pushdown-automata) playing the part of finite automata. The course states it as two theorems:

> **Theorem 1.** Given a language $L$ generated by a [context-free grammar](/courses/theory-of-computation/context-free-grammars), there is a PDA that accepts exactly $L$.
>
> **Theorem 2.** Given a language $L$ accepted by a PDA, there is a context-free grammar that generates exactly $L$.

Together they say that the [context-free languages](/courses/theory-of-computation/context-free-grammars) are exactly the languages pushdown automata accept, which is the "pushdown automaton" entry in the type 2 row of the [Chomsky hierarchy](/courses/theory-of-computation/grammars#the-chomsky-hierarchy).

## From a grammar to a PDA

The proof of Theorem 1 is a construction, and you can carry it out by hand. Start from a grammar in [Chomsky Normal Form](/courses/theory-of-computation/normal-forms), so every rule is $X \rightarrow YZ$ or $X \rightarrow a$. The PDA uses one central POP box to run a leftmost derivation directly on the stack:

1. START, then **PUSH $S$**, then go to the POP.
2. For every rule $X \rightarrow YZ$: an edge labelled $X$ out of the POP, then **PUSH $Z$**, then **PUSH $Y$**, then back to the POP. Because a stack is LIFO, $Z$ goes in first so that $Y$ ends up on top and gets popped next, keeping the derivation left to right.
3. For every rule $X \rightarrow a$: an edge labelled $X$ out of the POP into a READ box, and an edge labelled $a$ from that READ back to the POP. Expanding the leftmost variable to $a$ means the next unread letter on the tape must be $a$ (if it isn't, READ crashes).
4. An edge labelled $\Delta$ out of the POP (the stack is empty) into a READ, and from there an edge labelled $\Delta$ (the input is used up) to ACCEPT.

Convert $S \rightarrow aSb \mid \Lambda$ to CNF first (leaving $\Lambda$ aside for a moment):

$$
S \rightarrow T_1 V_1 \mid T_1 T_2 \qquad V_1 \rightarrow S T_2 \qquad T_1 \rightarrow a \qquad T_2 \rightarrow b
$$

Step through `aabb` and watch the line beside the stack. At each return to the POP box, the letters read so far followed by the stack from the top down spell one [sentential form](/courses/theory-of-computation/grammars#derivations) of a [leftmost derivation](/courses/theory-of-computation/context-free-grammars#leftmost-and-rightmost-derivations):

1. Start pushes $S$. Stack: `S` (sentential form: $S$).
2. Pop $S$, apply $S \rightarrow T_1 V_1$, push $V_1$ then $T_1$. Stack: `T₁ V₁` ($T_1 V_1$).
3. Pop $T_1$, apply $T_1 \rightarrow a$, READ `a`. Stack: `V₁` ($a V_1$).
4. Pop $V_1$, apply $V_1 \rightarrow S T_2$, push $T_2$ then $S$. Stack: `S T₂` ($a S T_2$).
5. Pop $S$, apply $S \rightarrow T_1 T_2$, push $T_2$ then $T_1$. Stack: `T₁ T₂ T₂` ($a T_1 T_2 T_2$).
6. Pop $T_1$, apply $T_1 \rightarrow a$, READ `a`. Stack: `T₂ T₂` ($aa T_2 T_2$).
7. Pop $T_2$, apply $T_2 \rightarrow b$, READ `b`. Stack: `T₂` ($aab T_2$).
8. Pop $T_2$, apply $T_2 \rightarrow b$, READ `b`. Stack: empty ($aabb$).
9. Pop $\Delta$ (empty stack) $\rightarrow$ READ finds $\Delta$ (end of input) $\rightarrow$ ACCEPT.

Notice what happens if the word is wrong: on `aab`, step 8 tries to READ `b` and finds $\Delta$ (crashes); on `aabbb`, step 9 pops $\Delta$ and goes to READ, which finds the leftover `b` instead of $\Delta$ (crashes). A word reaches ACCEPT exactly when some leftmost derivation produces it.

Because each rule is applied by one POP (steps 2 through 8 above), and a CNF derivation of a word of length $n$ uses exactly $2n - 1$ rules, the PDA pops exactly $2n - 1$ variables on an accepting run. For `aabb` ($n = 4$), count seven variable pops.

Now edit the grammar to `S -> AbA | BaB`, `A -> aA | a`, `B -> bB | b` from the exercise sheet and build again. There are several edges with the same label out of the POP, so the machine is nondeterministic: it has to guess which rule to use, just as you do when you derive a word by hand.

<Callout tone="orange" label="Pushing in reverse order">
  A frequent mistake in Theorem 1 is writing `PUSH Y` then `PUSH Z` for $X \rightarrow YZ$. That leaves $Z$ on top of the stack instead of $Y$, which turns the grammar backwards (turning $S \rightarrow aSb$ into $bSa$). Always push the right-hand side **backwards**, $Z$ first and $Y$ last, so the leftmost symbol $Y$ sits on top.
</Callout>

<Callout tone="orange" label="When Λ is in the language">
  A CNF grammar can't generate $\Lambda$, so a PDA built from it rejects the empty word. Some textbooks fix this by adding a loop at the POP for $S \rightarrow \Lambda$, which is safe **only** when $S$ never appears on a right-hand side (if $S$ does appear on a right-hand side, as in $V_1 \rightarrow S T_2$ above, a shortcut erasing $S$ at the POP would let an inner $S$ vanish mid-derivation). The box above uses a version that is always safe: a second branch out of START that reads $\Delta$ and accepts, so it accepts the empty word and nothing else.
</Callout>

## From a PDA to a grammar

Theorem 2 is the harder direction, and exams usually ask for its statement rather than its construction. Still, the core idea is intuitive: define one variable $A_{p, q}$ for every pair of boxes $(p, q)$ in the PDA, representing all input strings that carry the machine from $p$ to $q$ starting and ending at the **same** stack height (with the stack never dipping below that height in between). Because everything pushed and popped during that trip sits above whatever was already on the stack, two trips glue together sequentially ($A_{p, q} \rightarrow A_{p, r} A_{r, q}$), and a push-then-pop pair that adds and later removes the same symbol wraps around an inner trip. Anything a PDA can accept, a grammar built from those trip variables can generate.

## What it means

Every context-free grammar comes with a machine that recognizes its language, using one stack. That machine is usually nondeterministic. Real parsers can't guess, so they restrict the grammar enough that the next input letter always tells them which rule to use. Then the same machine becomes deterministic.

Some languages need more than one stack. $a^nb^nc^n$ has to compare three counts, and a single stack can only compare two before it's used up: if you push $a$'s and pop them against $b$'s, the stack is empty when the $c$'s arrive so the count $n$ is gone; if you push $b$'s on top of the $a$'s instead, the LIFO stack buries the $a$'s underneath. So $a^nb^nc^n$ is context-sensitive, not context-free. A machine with two stacks turns out to be as powerful as a Turing machine, the model behind everything a computer can compute. That's where the Chomsky hierarchy, and courses after this one, go next.

## Where this shows up today

<ApplicationsGrid>
  <PracticalApplication title="Top-down parsers" tool="LL PARSING">
    An LL parser is this exact machine: a stack that starts with the start symbol, expanding the variable on top or matching the terminal on top against the input. It decides which rule to use by looking at the next token in a table built from FIRST and FOLLOW sets, which is how a compiler course makes the construction deterministic.
  </PracticalApplication>
  <PracticalApplication title="Parser generators" tool="ANTLR / BISON">
    Hand a parser generator a grammar and it hands back a parser: a stack machine built from the rules. Theorem 1 is the reason that's always possible, and the restrictions these tools put on grammars are what make the machine deterministic.
  </PracticalApplication>
