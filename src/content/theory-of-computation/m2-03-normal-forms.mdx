# Simplifying Grammars and Normal Forms

People write grammars to be readable, so real grammars are full of rules that make algorithms awkward: rules that produce nothing ($M \rightarrow \Lambda$), rules that just rename a variable ($A \rightarrow B$), and variables that never contribute to any word. A **normal form** is a fixed shape that every rule must have. Any [context-free grammar](/courses/theory-of-computation/context-free-grammars) can be rewritten into one without changing the language (apart from $\Lambda$, as you'll see), and once every rule has the same shape, proofs and parsing algorithms get much simpler.

To standardize a context-free grammar, you clean it up in three steps and then convert it into **Chomsky Normal Form**. A second normal form, **Greibach Normal Form**, uses a different rule shape for top-down parsing.

## Removing Λ-productions

A **Λ-production** is a rule $X \rightarrow \Lambda$. A variable is **nullable** if it can derive $\Lambda$, either in one step ($X \rightarrow \Lambda$) or through a chain of nullable variables ($Y \rightarrow AB$ where both $A$ and $B$ can derive $\Lambda$). To remove the $\Lambda$-productions:

1. **Find every nullable variable** in passes: first mark every variable with a direct rule $X \rightarrow \Lambda$; then repeat until nothing new gets marked, marking any variable $Y$ that has a rule $Y \rightarrow Z_1 Z_2 \cdots Z_k$ where every symbol $Z_i$ is already marked nullable.
2. **Delete** all $\Lambda$-rules ($X \rightarrow \Lambda$).
3. **Add shortened copies:** wherever a nullable variable appears on a right-hand side, add a copy of that rule with the variable left out (one copy for each non-empty combination of leaving nullable variables out). Never add a new $X \rightarrow \Lambda$ rule here; if every symbol on a right-hand side is nullable, Step 1 already marked $X$ nullable.

For example, if $S \rightarrow AA$ and $A \rightarrow a \mid \Lambda$, then both $A$ (directly) and $S$ (via $AA$) are nullable. Leaving out one $A$ in $S \rightarrow AA$ adds $S \rightarrow A$ (leaving out both would give $\Lambda$, which we skip), leaving $S \rightarrow AA \mid A$ and $A \rightarrow a$.

Now work a complete example:

$$
S \rightarrow aMb \qquad M \rightarrow aMb \mid \Lambda
$$

$M$ is nullable (and $S$ is not, since every rule for $S$ contains terminals $a$ and $b$). Delete $M \rightarrow \Lambda$, then drop $M$ from $aMb$ in both rules to get $ab$:

$$
S \rightarrow aMb \mid ab \qquad M \rightarrow aMb \mid ab
$$

Every word is still there: anything that used $M \rightarrow \Lambda$ now uses one of the new $ab$ rules instead. The one exception is $\Lambda$ itself. If the [start variable](/courses/theory-of-computation/grammars#the-four-parts-of-a-grammar) is nullable, the language contains $\Lambda$, and a grammar with no $\Lambda$-rules can't produce it. The normal forms below describe $L - \{\Lambda\}$; if you ever need to keep $\Lambda$ in the language, add a fresh start variable $S_0 \rightarrow S \mid \Lambda$ at the very end.

## Removing unit productions

A **unit production** has a single variable on each side, like $A \rightarrow B$. Rules with a single terminal, like $A \rightarrow a$, are **not** unit productions and stay untouched. A unit production doesn't produce any letters; it just renames a variable, and a self-rule like $A \rightarrow A$ does nothing at all and can be dropped outright.

To remove unit productions, find for each variable $A$ every variable $B$ that $A$ can reach using unit rules alone, give $A$ every non-unit rule of each such $B$, and then delete all unit rules. Work an example with a unit cycle step by step:

$$
S \rightarrow aA \qquad A \rightarrow a \mid B \qquad B \rightarrow A \mid bb
$$

1. **Find unit-reachable variables:** $S$ has no unit rules, so it reaches only $\{S\}$. $A$ reaches $B$ (via $A \rightarrow B$), so $A$ reaches $\{A, B\}$. $B$ reaches $A$ (via $B \rightarrow A$), so $B$ reaches $\{B, A\}$.
2. **Copy non-unit rules:** $A$ already has $A \rightarrow a$, and inherits $B \rightarrow bb$ as $A \rightarrow bb$. $B$ already has $B \rightarrow bb$, and inherits $A \rightarrow a$ as $B \rightarrow a$.
3. **Delete unit rules** ($A \rightarrow B$ and $B \rightarrow A$):

$$
S \rightarrow aA \qquad A \rightarrow a \mid bb \qquad B \rightarrow bb \mid a
$$

Notice that $B$ is now unreachable from $S$, which is the next kind of clean-up.

## Removing useless variables

A variable is **useless** for either of two reasons:
- It is **non-generating**: it can never derive any string of terminals (for instance, $B \rightarrow bB$ loops forever with no base rule).
- It is **unreachable**: no derivation starting from $S$ can ever reach it (like $B$ in the result above).

Work a quick example to see why order matters here too:

$$
S \rightarrow a \mid AB \qquad A \rightarrow a \qquad B \rightarrow bB
$$

1. **Remove non-generating variables first:** $A$ generates $a$, and $S$ generates $a$. $B$ only has $B \rightarrow bB$, so $B$ can never turn into terminals. Delete $B$ and every rule that mentions $B$ ($B \rightarrow bB$ and $S \rightarrow AB$), leaving $S \rightarrow a$ and $A \rightarrow a$.
2. **Remove unreachable variables second:** starting from $S \rightarrow a$, the only reachable variable is $S$. Now $A$ is unreachable, so delete $A \rightarrow a$, leaving just $S \rightarrow a$.

If you checked reachability *before* generation, $A$ would still look reachable through $S \rightarrow AB$, and you would leave dead rules behind. Removing non-generating variables first, then unreachable ones, cleans out both. Removing useless variables and their rules never changes the language, and keeps the CNF result small.

## Chomsky Normal Form

A grammar is in **Chomsky Normal Form** (CNF) if every rule has one of two shapes:

$$
A \rightarrow BC \qquad \text{or} \qquad A \rightarrow a
$$

Each right-hand side is either two variables (which can be the same variable, like $A \rightarrow BB$) or one terminal. So $S \rightarrow AS \mid a$, $A \rightarrow SA \mid b$ is in CNF, whereas $S \rightarrow AAS$ (three variables), $A \rightarrow aa$ (two terminals), and $B \rightarrow aC$ (a terminal paired with a variable) are not.

After the three clean-ups, two more steps finish the conversion:

4. In every rule with two or more symbols on the right-hand side, replace each terminal $a$ by a new variable $T$, and add $T \rightarrow a$.
5. Split every rule $A \rightarrow B_1 B_2 \cdots B_k$ with $k > 2$ into $A \rightarrow B_1 V$ and $V \rightarrow B_2 \cdots B_k$, with a new variable $V$, and repeat until every right-hand side has exactly two variables.

Work through `S -> ABa, A -> aab, B -> Ac` step by step before stepping through the converter below:

- **Steps 1 to 3 (clean-up):** There are no $\Lambda$-productions and no unit productions. Every variable generates a terminal string ($A \Rightarrow aab$, $B \Rightarrow aabc$, $S \Rightarrow aabaabca$) and every variable is reachable from $S$, so nothing is removed.
- **Step 4 (isolate terminals):** Introduce $T_1 \rightarrow a$, $T_2 \rightarrow b$, and $T_3 \rightarrow c$, then replace every terminal inside the three multi-symbol rules:
  $$S \rightarrow ABT_1 \qquad A \rightarrow T_1 T_1 T_2 \qquad B \rightarrow AT_3$$
  Notice that $B \rightarrow Ac$ needed $T_3 \rightarrow c$ too, because mixing a variable and a terminal on the right-hand side is not allowed in CNF.
- **Step 5 (split rules longer than 2):** $B \rightarrow AT_3$ already has two variables, so it stays. Break the other two from the left:
  - $S \rightarrow ABT_1$ becomes $S \rightarrow AV_1$ and $V_1 \rightarrow BT_1$.
  - $A \rightarrow T_1 T_1 T_2$ becomes $A \rightarrow T_1 V_2$ and $V_2 \rightarrow T_1 T_2$.

Try stepping through this grammar in the converter, then convert your own grammars: try `S -> aSb | ε` (watch the note about $\Lambda$) and the expression grammar `E -> E+E | E*E | (E) | a`.

\end{aligned}
$$

### Why Chomsky Normal Form helps

In CNF, every [parse tree](/courses/theory-of-computation/context-free-grammars#parse-trees) is a binary tree: each $A \rightarrow BC$ rule splits one variable into two, and each $A \rightarrow a$ rule turns one variable into one letter. Starting from 1 symbol ($S$), each $A \rightarrow BC$ step increases the symbol count by 1, so reaching $n$ variables takes $n - 1$ binary steps, and turning those $n$ variables into $n$ letters takes $n$ terminal steps. Every derivation of a word of length $n \ge 1$ therefore takes **exactly $2n - 1$ steps**, no matter how the grammar is written.

That fixed structure makes CNF the starting point for proofs about [context-free languages](/courses/theory-of-computation/context-free-grammars), and for the **CYK algorithm**, which the box above uses. CYK uses [dynamic programming](/courses/algorithm-design-and-analysis/dynamic-programming) to decide whether a CNF grammar generates a word: it fills a table storing which variables derive each substring, starting with length-1 substrings (matched directly against rules $A \rightarrow a$) and building up to longer substrings by trying every split point $k$ to match $A \rightarrow BC$. It runs in $O(n^3)$ time for a word of length $n$.

<Callout tone="orange" label="Order and shape mistakes in CNF">
  Three traps when converting to CNF by hand:
  - **Order matters:** Remove $\Lambda$-productions before unit productions. Removing $\Lambda$-rules can create new unit rules (dropping $M$ from $A \rightarrow aM$ is fine, but dropping it from $A \rightarrow BM$ leaves $A \rightarrow B$), so doing it the other way around leaves unit rules behind.
  - **No mixed rules:** $B \rightarrow Ac$ and $A \rightarrow aB$ are **not** in CNF. Replace the terminal with $T \rightarrow c$ or $T \rightarrow a$ so the right-hand side has two variables.
  - **Convert before running CYK:** CYK checks splits into two variables ($A \rightarrow BC$) and single letters ($A \rightarrow a$), so it only works after the grammar is in CNF.
</Callout>

## Greibach Normal Form

A grammar is in **Greibach Normal Form** (GNF) if every rule is a single terminal followed by zero or more variables:

$$
A \rightarrow a V_1 V_2 \cdots V_k \qquad (k \ge 0)
$$

Because $k \ge 0$ includes $k = 0$, single-terminal rules like $B \rightarrow b$ are valid GNF rules too. So $S \rightarrow cAB$, $A \rightarrow aA \mid bB \mid b$, $B \rightarrow b$ is in GNF, while $S \rightarrow abSb \mid aa$ is not, because terminals ($b$ in $abSb$ and the second $a$ in $aa$) appear after the first symbol.

To fix $S \rightarrow abSb \mid aa$, keep the leading terminal $a$ at position 1 and replace every terminal at position 2 or later with a new variable ($T_a \rightarrow a$, $T_b \rightarrow b$):

$$
S \rightarrow aT_bST_b \mid aT_a \qquad T_a \rightarrow a \qquad T_b \rightarrow b
$$

Now every right-hand side begins with a single terminal and has only variables after it.

In GNF, every derivation step produces exactly one terminal, so a word of length $n$ takes exactly $n$ steps, and a parser always knows which letter the next rule must start with. That makes GNF useful for top-down parsing. Converting a general grammar to GNF takes more work than converting to CNF, though. If a rule starts with a variable ($S \rightarrow Ba$), you must expand $B$'s rules until a terminal appears in front. That breaks if the grammar has **left recursion**, where a variable begins its own right-hand side (such as $E \rightarrow E + T \mid T$), so you first rewrite left recursion to the right ($E \rightarrow T \mid T E'$ with $E' \rightarrow + T \mid + T E'$).

<Callout tone="orange" label="GNF allows only one leading terminal">
  A common mistake is stopping as soon as a rule *starts* with a terminal, like $S \rightarrow abB$. GNF requires **one** terminal at the front followed purely by variables, so $b$ in the second position must still be replaced by a variable ($T_b \rightarrow b$), giving $S \rightarrow a T_b B$.
</Callout>

## Where this shows up today

<ApplicationsGrid>
  <PracticalApplication title="Parsing natural language" tool="NLP">
    Statistical parsers for English and other languages use a probabilistic version of CYK (often called CKY) on grammars in Chomsky Normal Form, filling the same table of substrings but keeping the most likely tree for each cell.
  </PracticalApplication>
  <PracticalApplication title="Left recursion and top-down parsers" tool="COMPILERS">
    Hand-written recursive-descent parsers can't use a rule like E → E + T directly, because the function for E would call itself forever. Rewriting the grammar to remove left recursion, the hard part of reaching GNF, is a standard step before writing such a parser.
  </PracticalApplication>
</ApplicationsGrid>
