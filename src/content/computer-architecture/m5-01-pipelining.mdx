# Pipelining

Doing laundry involves four steps: wash, dry, fold, and store. If you finish one load completely before starting the next, the washing machine sits idle for most of the afternoon. A better workflow starts the second load in the washer the moment the first load moves to the dryer.

<LaundryPipeline />

Each load still takes the same total time from dirty clothes to folded stack. The gain comes from overlap: loads finish much more often. That is the core idea of **pipelining**. It does not shorten the **latency** (the time needed to complete one individual instruction). Instead, it multiplies **throughput** (the number of instructions completed per second).

## The five classic stages

In an unpipelined single-cycle processor, each instruction must crawl through the entire datapath before the next instruction can begin. The [machine cycle](/courses/computer-organization/machine-cycle) breaks naturally into five sequential steps:

| Stage | Name | Functional Hardware | Primary Hardware Action |
|---|---|---|---|
| **IF** | Instruction Fetch | [Program Counter](/courses/computer-architecture/ripple-and-synchronous-counters#the-program-counter), Instruction Memory / I-Cache, Incrementer Adder | Reads 32-bit instruction from memory at address PC; increments PC by 4 |
| **ID** | Instruction Decode & Register Read | [Control Unit](/courses/computer-architecture/control-unit), [Register File](/courses/logic-design/registers), Sign Extender | Decodes opcode bits; reads source registers $rs_1$ and $rs_2$; sign-extends immediate |
| **EX** | Execute / Address Calculation | [Arithmetic Logic Unit (ALU)](/courses/computer-organization/inside-the-cpu), Branch Comparator | Performs arithmetic operation, calculates effective memory address, or evaluates branch |
| **MEM** | Memory Access | Data Memory / D-Cache | Reads data for `LOAD` or writes data for `STORE`; passes through ALU results |
| **WB** | Write Back | Register File Write Port | Writes result from ALU or memory into destination register $rd$ |

To understand how each stage operates, consider the hardware components that power them:

- **Sign extender**: A combinational circuit in the ID stage that takes an immediate constant (such as a 16-bit offset in MIPS) and replicates its most significant bit (the sign bit) across all upper 16 bit positions. This converts a 16-bit signed integer into a 32-bit two's complement value without altering its numerical sign or magnitude.
- **Branch comparator**: A dedicated comparison circuit that compares register values directly to determine whether a conditional jump is taken. While early designs used the main ALU for branch evaluation, modern pipelines evaluate branches using dedicated comparators to resolve decisions earlier in the datapath.
- **Register file**: A centralized array of processor registers featuring multiple independent read and write ports. In a typical RISC core, the register file provides two 32-bit read ports (allowing simultaneous access to $rs_1$ and $rs_2$) and one 32-bit write port (updating destination register $rd$).

To overlap these operations, the processor places an edge-triggered **pipeline register** between every pair of stages: `IF/ID`, `ID/EX`, `EX/MEM`, and `MEM/WB`.

At each rising clock edge, every pipeline register captures the output data and control signals from the preceding stage. The next stage reads those values and performs its combinational work over the remainder of the clock cycle. The edge-triggered [flip-flops](/courses/logic-design/flip-flops) prevent signals from running into each other, isolating five separate instructions running concurrently on different hardware units.

### Inside the pipeline registers

Pipeline registers do not just carry data words; they carry the instruction's identity and its dedicated control signals down the pipeline. Control signals generated by the control unit in the ID stage must travel synchronously alongside the data so each stage receives its specific commands during the exact clock cycle the instruction reaches that stage:

- **`IF/ID` register**: Holds the 32-bit fetched instruction word and the incremented $PC$ value ($PC + 4$), which is needed later if the instruction is a branch or subroutine jump.
- **`ID/EX` register**: Holds the two operand values read from the register file, the 32-bit sign-extended immediate offset, the register addresses of source and destination registers, and the control lines for execution (`ALUOp`, `ALUSrc`, and destination register selector `RegDst`).
- **`EX/MEM` register**: Holds the 32-bit ALU result (which serves as an arithmetic value or an effective memory address), the data word read from $rs_2$ (destined to be stored in memory during a `STORE`), the target branch address, the zero/condition flags, and memory control signals (`MemRead`, `MemWrite`, `Branch`).
- **`MEM/WB` register**: Holds the data word read from data memory (if a `LOAD`), the ALU result (if an arithmetic instruction), the destination register address $rd$, and write-back control signals (`RegWrite`, `MemtoReg`).

### Resolving the register file access conflict

The register file is accessed in two different stages: ID reads operand registers, while WB writes destination registers. If an instruction in WB writes to register $R_1$ during the same clock cycle that a subsequent instruction in ID reads register $R_1$, the read operation might capture stale data.

Processors solve this without pipeline stalls through **two-phase clocking**:

1. **First half-cycle (falling edge or high phase)**: The write-back stage updates the destination register.
2. **Second half-cycle (rising edge or low phase)**: The decode stage reads the source registers.

Because writes happen before reads within the same clock period, the instruction in ID reads the freshly updated value rather than the old one. If two-phase clocking is unavailable, hardware designers implement internal register write-to-read forwarding multiplexers directly inside the register file, routing the incoming write bus directly to the read output ports whenever the read address matches the write address.

## How much faster?

Consider running $n$ independent instructions on a processor with $k$ pipeline stages.

In an unpipelined processor where each instruction takes $k$ cycles:

$$
\text{Total Cycles}_{\text{unpipelined}} = n \times k
$$

In a pipelined processor, the first instruction enters the pipeline and takes $k$ cycles to fill the pipe and emerge from WB. After that initial latency, exactly one instruction completes on every subsequent clock cycle:

$$
\text{Total Cycles}_{\text{pipelined}} = k + (n - 1)
$$

The ideal speedup in cycle count is:

$$
\text{Speedup}_{\text{ideal}} = \frac{n \times k}{k + n - 1}
$$

As the program length $n$ becomes very large ($n \gg k$), the ratio $\frac{n}{k + n - 1}$ approaches 1. The cycle speedup approaches the number of pipeline stages:

$$
\lim_{n \to \infty} \text{Speedup} = k
$$

For 1,000 instructions on a 5-stage pipeline:

$$
\text{Cycles}_{\text{unpipelined}} = 1000 \times 5 = 5000\text{ cycles}
$$

$$
\text{Cycles}_{\text{pipelined}} = 5 + (1000 - 1) = 1004\text{ cycles}
$$

$$
\text{Speedup} = \frac{5000}{1004} \approx 4.98
$$

### Clock period: stage imbalance and register overhead

In a physical silicon chip, actual speedup does not equal the theoretical stage count $k$ because the clock period of a pipelined processor is constrained by two physical factors:

1. **Stage imbalance**: The clock cycle must be long enough to accommodate the **slowest stage**. If four stages take 150 picoseconds and one stage takes 250 picoseconds, the clock period must be at least 250 picoseconds. The faster stages finish early and sit idle for the remaining padding time ($\Delta t_i = \max(t_j) - t_i = 100\text{ ps}$), wasting throughput.
2. **Register overhead**: The interstage pipeline registers add physical delays that do not exist in an unpipelined datapath. The total register overhead $t_{\text{reg}}$ combines three physical metrics:
   - **Setup time** ($t_{\text{setup}}$): The minimum duration the input signal must remain steady and valid before the clock edge arrives.
   - **Clock-to-Q delay** ($t_{\text{cq}}$): The propagation delay between the active clock edge and the moment the flip-flop output stabilizes with the new data word.
   - **Clock skew** ($t_{\text{skew}}$): The spatial arrival time variation of the clock signal across different physical flip-flops on the silicon die, caused by wire resistance, parasitic capacitance, and on-chip thermal variations.

Thus, the total register delay added to each stage is $t_{\text{reg}} = t_{\text{setup}} + t_{\text{cq}} + t_{\text{skew}}$.

Let $t_i$ be the combinational logic delay of stage $i$. The unpipelined clock period is the sum of all stage delays:

$$
T_{\text{unpipelined}} = \sum_{i=1}^k t_i
$$

The pipelined clock period is governed by the critical path of the slowest stage plus register overhead:

$$
T_{\text{pipelined}} = \max_{1 \le i \le k}(t_i) + t_{\text{reg}}
$$

The true execution time speedup is:

$$
\text{Speedup}_{\text{actual}} = \frac{T_{\text{unpipelined\_total}}}{T_{\text{pipelined\_total}}} = \frac{n \times \sum_{i=1}^k t_i}{[k + (n - 1)] \times (\max(t_i) + t_{\text{reg}})}
$$

As $n \to \infty$:

$$
\text{Speedup}_{\max} = \frac{\sum_{i=1}^k t_i}{\max(t_i) + t_{\text{reg}}}
$$

**Pipeline efficiency** measures how close the implementation comes to the theoretical $k$-fold speedup:

$$
\text{Efficiency} = \frac{\text{Speedup}}{k} \times 100\%
$$

## Why not 100 stages?

If dividing execution into 5 stages gives a nearly 5-fold speedup, dividing into 100 stages should yield a 100-fold speedup. High-frequency designs in the early 2000s (such as the Intel Pentium 4 Prescott with 31 stages) pursued deep pipelining, known as **superpipelining**. However, several physical boundaries restrict pipeline depth:

1. **Unbalanced logic partitioning**: You cannot divide digital logic arbitrarily. A 32-bit carry-lookahead adder, an ALU shifter, or a cache address decoder requires a minimum tree of gate levels (typically 4 to 6 gate delays). Slicing logic finer than this requires inserting flip-flops inside atomic arithmetic units, which introduces synchronization overhead and worsens stage imbalance.
2. **Accumulating register overhead**: As the clock period shrinks into tens of picoseconds, fixed register delay $t_{\text{reg}}$ (typically 15 to 30 ps) consumes an increasing percentage of each cycle. With a 200 ps clock, a 25 ps register overhead represents 12.5% waste. With a 50 ps clock, that same 25 ps overhead wastes 50% of the entire cycle. Beyond a certain depth, adding another pipeline register increases total execution time rather than reducing it.
3. **Hazard penalties multiply**: When a branch is mispredicted or a data dependency forces a stall, the CPU flushes all instructions currently in flight. In a 5-stage pipeline, resolving a branch in stage 3 costs 2 wasted cycles. In a 30-stage pipeline, resolving a branch in stage 15 flushes 14 cycles of work.
4. **Clock skew and power dissipation**: Distributing a gigahertz clock signal across millions of interstage flip-flops without phase distortion (skew) requires massive clock tree buffers that consume huge electrical power ($P = \alpha C V^2 f$) and generate intense localized heat.

Modern high-performance cores (such as ARM Cortex-A78, Apple M-series, and AMD Zen 4) balance these trade-offs by choosing moderate pipeline depths between 12 and 19 stages.

## Traps and pitfalls

<Callout tone="orange" label="Trap: Pipelining does not reduce individual instruction latency">
Pipelining increases instruction throughput, not individual execution speed. In fact, an individual instruction takes slightly longer to complete in a pipelined processor than in an unpipelined multicycle processor because each stage duration is padded to match the slowest stage, and interstage register latch delays add overhead.
</Callout>

<Callout tone="orange" label="Trap: Assuming registers write and read simultaneously without circuit support">
A common misconception is that the WB stage and ID stage can share the register file simultaneously without special hardware. Without dual-phase clocking or internal write-to-read forwarding inside the register file, reading a register being written in the same cycle produces stale data.
</Callout>

<Callout tone="orange" label="Trap: The k-fold speedup myth">
Students often assume that dividing a CPU into $k$ pipeline stages makes programs run $k$ times faster. In practice, speedup is substantially lower due to three compounding factors: stage imbalance forces all stages to wait for the slowest stage, pipeline register setup and propagation delays add fixed overhead to every cycle, and pipeline hazard stalls (data dependencies, branch mispredictions, and cache misses) inject idle bubble cycles.
</Callout>

<Callout tone="orange" label="Trap: Pipelining short programs yields negligible speedup">
The formula $\text{Cycles} = k + n - 1$ shows that for small instruction counts ($n \le k$), the pipeline fill time dominates. For $n = 5$ instructions on a 5-stage pipeline, execution takes $5 + 5 - 1 = 9$ cycles compared to $5 \times 5 = 25$ cycles unpipelined, achieving only a $2.78\times$ speedup rather than $5\times$. Pipelining requires large instruction streams ($n \gg k$) to approach theoretical efficiency.
</Callout>

<Callout tone="violet" label="Historical context: From 8086 queues to modern superscalar pipelines">
The Intel 8086 used a primitive two-stage pipeline: a Bus Interface Unit prefetching bytes into a 6-byte queue while an Execution Unit executed instructions. The RISC revolution (Patterson's Berkeley RISC and Hennessy's Stanford MIPS) proved that streamlining instructions to equal lengths allowed uniform 5-stage pipelines. Modern **superscalar** processors replicate these pipelines, issuing 4 to 8 instructions every cycle into parallel execution units.
</Callout>

## Worked practice problems

### Problem 1: Quantitative pipeline speedup, stage imbalance, and latch overhead

A non-pipelined single-cycle processor has the following combinational stage delays:

- Instruction Fetch (IF): $200\text{ ps}$
- Instruction Decode (ID): $150\text{ ps}$
- Execute (EX): $250\text{ ps}$
- Memory Access (MEM): $220\text{ ps}$
- Write Back (WB): $160\text{ ps}$

An engineering team redesigns this datapath into a 5-stage pipeline. Adding an edge-triggered pipeline register between stages introduces a register setup and propagation delay of $t_{\text{reg}} = 20\text{ ps}$.

Calculate:
1. The clock period of the unpipelined processor and the total time required to execute $1,000$ instructions.
2. The clock period of the 5-stage pipelined processor and the total time required to execute $1,000$ instructions (assuming ideal conditions with no hazard stalls).
3. The speedup achieved for $1,000$ instructions, the asymptotic speedup limit ($n \to \infty$), and the pipeline efficiency.
4. The instruction throughput of the pipelined processor in MIPS (Million Instructions Per Second).

<ModelAnswer>
**Part 1: Unpipelined clock period and total execution time:**

In an unpipelined single-cycle processor, one instruction must traverse all five functional blocks in a single clock cycle:

$$T_{\text{unpipelined}} = \sum_{i=1}^5 t_i = 200 + 150 + 250 + 220 + 160 = 980\text{ ps}$$

Total time to execute $n = 1,000$ instructions:

$$T_{\text{unpipelined\_total}} = n \times T_{\text{unpipelined}} = 1000 \times 980\text{ ps} = 980,000\text{ ps} = 980.0\text{ ns}$$

---

**Part 2: Pipelined clock period and total execution time:**

The clock period of the pipelined processor is determined by the slowest stage plus the register latch overhead:

$$\max(t_i) = t_{\text{EX}} = 250\text{ ps}$$

$$T_{\text{pipelined}} = \max(t_i) + t_{\text{reg}} = 250 + 20 = 270\text{ ps}$$

Total clock cycles required for $k = 5$ stages and $n = 1,000$ instructions:

$$\text{Cycles}_{\text{pipelined}} = k + n - 1 = 5 + 1000 - 1 = 1004\text{ cycles}$$

Total execution time:

$$T_{\text{pipelined\_total}} = 1004 \times 270\text{ ps} = 271,080\text{ ps} = 271.08\text{ ns}$$

---

**Part 3: Speedup and efficiency:**

Actual speedup for $n = 1,000$ instructions:

$$\text{Speedup} = \frac{T_{\text{unpipelined\_total}}}{T_{\text{pipelined\_total}}} = \frac{980,000\text{ ps}}{271,080\text{ ps}} \approx 3.615$$

Asymptotic speedup as $n \to \infty$:

$$\text{Speedup}_{\max} = \frac{T_{\text{unpipelined}}}{T_{\text{pipelined}}} = \frac{980\text{ ps}}{270\text{ ps}} \approx 3.630$$

Pipeline efficiency:

$$\text{Efficiency} = \frac{\text{Speedup}}{k} \times 100\% = \frac{3.615}{5} \times 100\% \approx 72.3\%$$

The efficiency is below 100% due to two factors: stage imbalance (the other four stages sit idle for part of each 270 ps cycle) and the 20 ps register overhead added to each stage.

---

**Part 4: Instruction throughput in MIPS:**

$$\text{Throughput} = \frac{n}{T_{\text{pipelined\_total}}} = \frac{1000\text{ instructions}}{271.08 \times 10^{-9}\text{ s}} \approx 3.689 \times 10^9\text{ instructions/s} \approx 3688.95\text{ MIPS}$$
</ModelAnswer>

### Problem 2: Deep pipelining trade-off analysis

A processor designer considers splitting the 5-stage pipeline from Problem 1 into an 8-stage superpipeline.
- By splitting the longer stages, the maximum combinational stage delay drops from $250\text{ ps}$ to $140\text{ ps}$.
- Each new interstage register adds $t_{\text{reg}} = 20\text{ ps}$, giving a new clock period of $T_{\text{super}} = 140 + 20 = 160\text{ ps}$.
- In the 5-stage pipeline, branch instructions represent $20\%$ of all instructions, and branch outcome resolution occurs in stage 3, incurring a 2-cycle penalty on misprediction. The branch misprediction rate is $10\%$.
- In the 8-stage pipeline, branch outcome resolution occurs in stage 5, incurring a 4-cycle penalty on misprediction. The branch misprediction rate remains $10\%$.
- Both designs achieve an ideal CPI of 1.0 in the absence of branch mispredictions.

Determine whether the 8-stage pipeline is faster than the 5-stage pipeline, calculating the effective CPI and average time per instruction for both designs.

<ModelAnswer>
**Part 1: Effective CPI of the 5-stage pipeline:**

The average stall cycles added per instruction by branch mispredictions is:

$$\text{Stall}_{\text{branch5}} = \text{Branch Frequency} \times \text{Mispredict Rate} \times \text{Penalty Cycles}$$

$$\text{Stall}_{\text{branch5}} = 0.20 \times 0.10 \times 2 = 0.04\text{ stall cycles/instruction}$$

$$\text{CPI}_5 = 1.0 + 0.04 = 1.04$$

Average execution time per instruction:

$$\text{Time}_5 = \text{CPI}_5 \times T_{\text{clk5}} = 1.04 \times 270\text{ ps} = 280.8\text{ ps/instruction}$$

---

**Part 2: Effective CPI of the 8-stage superpipeline:**

In the 8-stage pipeline, resolving branches in stage 5 increases the misprediction penalty to 4 cycles:

$$\text{Stall}_{\text{branch8}} = 0.20 \times 0.10 \times 4 = 0.08\text{ stall cycles/instruction}$$

$$\text{CPI}_8 = 1.0 + 0.08 = 1.08$$

Average execution time per instruction:

$$\text{Time}_8 = \text{CPI}_8 \times T_{\text{clk8}} = 1.08 \times 160\text{ ps} = 172.8\text{ ps/instruction}$$

---

**Part 3: Performance comparison:**

$$\text{Speedup} = \frac{\text{Time}_5}{\text{Time}_8} = \frac{280.8\text{ ps}}{172.8\text{ ps}} \approx 1.625$$

The 8-stage superpipeline is approximately $62.5\%$ faster. Even though the branch misprediction penalty doubled from 2 cycles to 4 cycles (raising CPI from 1.04 to 1.08), the clock frequency increased significantly (clock period dropped from 270 ps to 160 ps, a 40.7% reduction). The higher clock speed easily offsets the modest increase in branch stall cycles.
</ModelAnswer>
